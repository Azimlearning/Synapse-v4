# Plan: a chain of free OpenRouter models in front of the paid Anthropic key

> Written 2026-11-14 from the owner's request: "change from using a multi llm system using openrouter using some free models like nvidia nemotron and other free models and backups or fallbacks (maybe up to 3 fallback free llm), because sometimes it's rate limited, last choice is my paid anthropic api key."

## Why this exists

Every question the library cannot answer is generated by a model, and today that is always the paid Anthropic key. The monthly and all-time caps are nearly used up (about $0.15 of the all-time $10 left on 2026-11-14), so a miss can end in a refused run. The owner wants the free OpenRouter models to take the calls first, with up to three of them as fallbacks for each other when one is rate limited, and the paid key only as the last resort.

## What's already covered

- `LLMService` (`api/llm/service.py`) already tries providers in order on any `ProviderFailure`, reserves each attempt's worst case against the cap, and books every attempt in the ledger. It held one primary and one fallback; it now takes a list.
- Streaming (`on_text`, D-79) is part of the provider interface, so the new provider streams too.
- `OPENROUTER_API_KEY` already exists in `Settings` and `env_setup.md`; it was never wired.
- The pipeline's degrade ladder, its call budget and the verifier are unchanged: a free model's page is verified exactly like Anthropic's, so a worse model can fail more often but can never ship an unverified Environment (hard constraint 1).

## Scope

In:
1. `api/llm/providers/openrouter.py`: one provider per free model, OpenAI chat-completions shape, streaming, per-model cool-down.
2. A chain of up to three free models, then Anthropic: `LLM_FREE_CHAIN` (comma separated; empty means the default three; `off` means Anthropic only).
3. Free calls cost $0 and are never refused by a spend cap (a used-up cap must still let the free models answer).
4. `/health` reports the order the models are tried in (ids only).
5. Tests on a mock transport; no socket, no cost.

Out, with reasons:
- Paid OpenRouter models. The provider refuses any id that does not end in `:free`, so this path cannot bill. Mixing paid OpenRouter routes with the Anthropic key is a different decision.
- Per-purpose routing (free for `route` and `explain`, paid for `free` pages). The owner asked for one chain. Measure first (see Risks), then decide.
- Skipping the free models on a retry after a bad page. Worth doing if free pages fail verification often; not built until measured.
- A live call to OpenRouter in this session: the key is in the owner's `.env`, which the assistant does not read. The first live check is the owner's.

## Approach

Free models first, in order; the paid provider last. A provider failure of any kind moves the call to the next one. The OpenRouter provider maps every error to `transient` (or `timeout` / `truncated`), never to `auth`, `credit_exhausted` or `bad_request`: those kinds stop a whole run in the service, and a bad OpenRouter key or a withdrawn model must not stop the Anthropic last resort from getting the call. A failing model sits on a cool-down (`Retry-After` when sent, 60 s for a rate limit, 300 s for a refused key, 900 s for a withdrawn model) so later calls skip it with no network trip. Default chain, checked against `openrouter.ai/api/v1/models` on 2026-11-14: `nvidia/nemotron-3-ultra-550b-a55b:free`, `google/gemma-4-31b-it:free`, `inclusionai/ling-3.2-flash:free`.

## Risks & unknowns

| Risk | Confidence | Response |
|---|---|---|
| **Free-tier quota is small.** OpenRouter's docs (read 2026-11-14): 20 requests a minute, 50 a day with fewer than 10 credits ever bought, 1000 a day with 10 or more. One generated lab made 14 calls on 2026-11-14, so 50 a day is about 3 labs. | Read from the docs | Tell the owner. Buying 10 OpenRouter credits once (they need not be spent) lifts the daily limit to 1000. |
| **Free models write worse labs.** The Free lane asks for a whole page with 3 to 4 reading passes; a 550B reasoning model may do well, a small one may not. | Unmeasured | The verifier gates it. Measure the verified rate per model on the golden set before a demo; if low, restrict free models to cheap purposes. |
| **Free endpoints may keep and train on prompts.** | Stated by OpenRouter for free variants; not re-read this session | Prompts carry students' science questions and our prompt packs, no personal data. Check the account's data-policy setting. Never route anything personal here. |
| **Free ids disappear.** | Certain over weeks | `LLM_FREE_CHAIN` overrides the default; a 404 cools the model down for 15 minutes and the chain moves on. Re-check the list before a demo. |
| **A fall-through mid-stream** leaves the first model's partial text in the build log before the next model's text. | Read in `api/pipeline/run.py` | The log is text for reading, never run; only the verified block runs. Cosmetic. |
| **Reasoning models spend `max_tokens` on thinking** and return nothing. | Documented by OpenRouter | Treated as `truncated`: the chain moves on. |
| **Latency.** A free reasoning model can be slower than Sonnet; the Free lane already takes about 4 minutes. | Unmeasured | 120 s per-call timeout, then the next model. |

## Definition of done

- `uv run pytest api/llm` passes, including the chain, the cool-down, the free-calls-never-refused and the settings tests; ruff and pyright clean on `api/llm` and `api/core`.
- With `OPENROUTER_API_KEY` set and `SYNAPSE_LLM_MODE=live`, `/health` lists the three free ids then `anthropic`.
- The owner has run one question not in the library and `/spend` shows an `openrouter` row at $0, or an `anthropic` row only after the free models failed.
